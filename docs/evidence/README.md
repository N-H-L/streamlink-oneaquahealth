# Evidence files

Results of real runs, committed so they can be checked even when an external server is down.
The narrative log with dates and what each run means is `../hackathon/EVIDENCE.md`; the claim-by-claim
table is `../hackathon/CLAIMS.md`.

| File | What it is | How to reproduce |
|---|---|---|
| `validation-summary.md` | Official HL7 validator run over the IG artefacts, the transactions this app's own engine produces, the resources as stored after a full lifecycle, and 5 deliberately broken records. Per-file table with error, warning and info counts. | `npm run validate` (add `TX=https://tx.fhir.org/r4` for online terminology, as this run used) |
| `sandbox-demo.json` | The resource ids written to the **official OneAquaHealth FHIR sandbox** and read back, with the timestamp of the run. The sandbox is offline at the time of submission, so this is the durable record of that run. | `npm run sandbox` (writes), `node scripts/sandbox-cleanup.mjs --delete` (removes exactly these ids) |
| `sandbox-record-in-app.png` | StreamLink pointed at the sandbox, rebuilding a stream's whole timeline from resources on HL7 Europe's server. | `npm run dev`, Settings → OneAquaHealth sandbox |
| `record-timeline.png` | A finished record: check → verification → lab visit request → result, with the FHIR resources expandable underneath. | `npm run e2e` |
| `a11y.json` | axe-core (WCAG 2.1 A/AA rules) over the six main screens. | `npm run a11y` |

`out/` is not committed because it is regenerated by every run; these are copies taken at submission time.
