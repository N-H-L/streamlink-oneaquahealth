# Product contract — StreamLink (hackathon version)

## Primary user and problem
**City / OneAquaHealth stream-health coordinator.** They decide where scarce lab sampling goes. Their picture of each stream is years old: each of the 96 OAH lab sites was sampled in one campaign, 95 of them in 2023. Citizen reports exist, but they sit outside the health-data systems, their reliability is unknown, and they are not tied to any follow-up.
The secondary user is the **citizen volunteer**, who provides the reports and needs to see that they mattered.

## The one journey that proves value
1. A citizen at a stream does a 3-minute check (the OAH app's fields) and reports a sewage discharge.
2. Trust checks flag a contradiction. The citizen fixes it. The record is saved as **preliminary** FHIR.
3. The coordinator sees that stream rise in "needs a lab visit". The rank explains itself: map baseline + fresh event + data age.
4. The coordinator (or expert) verifies the report → **final**, which now also conforms to the official OAH profile. They issue a lab referral (ServiceRequest).
5. A lab result arrives and closes the referral (simulated in the demo, labelled). The citizen receives "your report led to a lab visit".
6. The same journey works for a new city (Singapore), added with one config file.

## Target
The overall top 3 (all tracks compete for one ranking). Declared track: 7, Digital Health Standards.
| Criterion | How we satisfy it |
|---|---|
| Impact 30 | A real data-age gap; ends in an action (a lab visit); closes the loop to citizens; three One Health pillars |

## Distinctive capability and its baseline
- **Standards conformance.** Baseline: ad-hoc or "experimental" FHIR exports (as seen in competitors). Evidence: HL7 validator 0 errors against OAH profiles, plus negative tests that fail as expected.
- **Map-context baseline.** Baseline: uniform/random ranking and the single best feature. Evidence: leave-one-city-out Spearman/AUROC.
- **Trust checks.** Baseline: accept all reports. Evidence: rule unit tests on crafted contradictions. Effectiveness on real data is **not claimed**: no labelled data exists.

## Acceptance criteria
- AC1: The check is completable at 390 px width. Offline submit queues and syncs later.
- AC2: A check produces a transaction Bundle (QR + preliminary Observations + wellbeing + Provenance with trust). **Validator: 0 errors** for all generated fixtures.
- AC3: A Bundle is written to and read back from a FHIR server. The local in-browser store is always available; the OAH sandbox is used only with user OK. Automated test.
- AC4: ≥ 8 trust rules, each with a plain-language message. The citizen can fix a flag; the resolution is stored.
- AC5: The record view shows a timeline, 3 pillars and per-pillar freshness for every OAH lab site + Singapore.
- AC6: The referral list shows a factor breakdown and adjustable weights. Accepting creates a ServiceRequest. A result Observation with basedOn completes it. A Communication is sent to the citizen.
- AC7: A model evaluation (leave-one-city-out vs baselines) is recorded honestly in EVIDENCE.md and in the UI "About the model".
- AC8: A Singapore config generated by a script runs AC1–AC6.
- AC9: Public repo: README (sections follow the criteria), license, reproduction commands. Static deploy.
- AC10: Lighthouse accessibility ≥ 90 on the main screens.

## Credibility notes (no invented traction)
- **Plausible adopters:** OAH city partners and municipal environment/public-health units. The OAH Open Information Hub is a natural home.
- **Operating cost:** static hosting (free tier) + an existing FHIR server. No paid AI.
- **Privacy:**
  - volunteers are pseudonymous (no name or contact details in FHIR)
  - photos are not uploaded to shared servers in the demo
  - wellbeing is self-reported and tied to the stream, not the person
- **Alternatives:**
  - OAH app (no FHIR, no follow-up loop)
  - miniSASS, CrowdWater, FreshWater Watch (collection only)
  - Catchment (sampling planner with unvalidated weights, no conformant FHIR)
